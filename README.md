# Рефакторинг системи з TDD (Meter Manager)

Курсова робота: рефакторинг успадкованої системи обліку енергоресурсів **Meter Manager** із застосуванням методології розробки через тестування (TDD). Система веде облік локацій, орендарів, лічильників, показників і тарифів та формує акти споживання в Excel.

На початку роботи серверна частина не мала жодного автоматизованого тесту. Під час роботи бекенд покрито модульними та інтеграційними тестами (Jest, supertest), під захистом тестів виправлено виявлені дефекти, а також виправлено генерацію актів споживання у фронтенді.

## 1. Структура проєкту

```
calculationPayments/
├── backend/      — серверна частина (REST API)
├── frontend/     — клієнтська частина (вебінтерфейс)
└── README.md
```

### /backend — серверна частина

REST API на Node.js (Express, Sequelize, PostgreSQL, авторизація через Auth0). Детальна інструкція: [backend/README.md](backend/README.md).

- `server.js` — підключення до БД і запуск сервера;
- `app.js` — налаштування Express-застосунку (CORS, JSON, Swagger, маршрути); винесено окремо, щоб тести працювали без запуску сервера;
- `config/` — налаштування підключення до БД (`config.js`) і документації Swagger (`swagger.js`);
- `models/` — моделі Sequelize (локації, орендарі, лічильники, показники, тарифи, користувачі тощо);
- `migrations/` — міграції структури БД;
- `src/routes/` — маршрути API;
- `src/middlewares/` — перевірка токена й ролей, валідація вхідних даних, спільний обробник помилок валідації;
- `src/controllers/` — обробка запитів і формування відповідей з правильними HTTP-статусами;
- `src/services/` — бізнес-логіка;
- `src/utils/` — допоміжні модулі: `consumptionCalculator.js` (розрахунок споживання), `withTransaction.js` (виконання операцій в одній транзакції);
- `src/tests/unit/` — модульні тести (20 наборів);
- `src/tests/integration/` — інтеграційні тести маршрутів (10 наборів);
- `Dockerfile`, `docker-compose.yml` — запуск у контейнері.

### /frontend — клієнтська частина

Застосунок на React (Vite, MUI, Auth0). Детальна інструкція: [frontend/README.md](frontend/README.md).

- `src/App.jsx`, `src/main.jsx` — точка входу та маршрутизація сторінок;
- `src/pages/` — сторінки: подача показників (`SubmitMetricsPage`), панель керування (`DashboardPage`), акти споживання (`ActPage`), сторінка заблокованого користувача (`BlockedUserPage`);
- `src/components/` — компоненти за розділами: `locations`, `tenants`, `meters`, `meter-tenants`, `meterReadings`, `tariffs`, `resourceTypes`, `resource-deliveries`, `users`, `acts`; спільні елементи інтерфейсу — у `ui` (вікно підтвердження, вибір дати, поле пошуку), бокове меню — `Sidebar.jsx`;
- `src/api/` — запити до REST API для кожної сутності (`baseApi.js` — базові налаштування);
- `src/hooks/` — хуки для завантаження та зміни даних (`useMeters`, `useTariffs`, `useMeterReadings` тощо);
- `src/contexts/AuthContext.jsx` — стан автентифікації користувача;
- `src/utils/` — `excelGenerator.js` (генерація Excel-актів), `translateError.js` і `uaDictionary.js` (переклад повідомлень про помилки українською);
- `src/theme/` — тема оформлення.

## 2. Підготовка до запуску

Середовище:
* Встановіть Node.js (версія 18+).
* В обох папках (`backend` та `frontend`) виконайте команду для встановлення залежностей:

```
npm install
```

Змінні середовища:
* У папці `backend` створіть файл `.env.development` за зразком `.env.example`: сервер читає змінні з `.env.<NODE_ENV>`, за замовчуванням — `.env.development`.
* У папці `frontend` створіть файл `.env` (змінні з префіксом `VITE_`, див. [frontend/README.md](frontend/README.md)).
* Для бекенду потрібні дані підключення до PostgreSQL і налаштування Auth0, для фронтенду — адреса API та налаштування Auth0.

> Для запуску тестів база даних і Auth0 не потрібні: у тестах вони замінені моками.

## 3. Запуск тестів

```
cd backend
npx jest
```

Запуск зі звітом покриття коду:

```
npx jest --coverage
```

У терміналі з'явиться таблиця покриття для кожного файлу, а HTML-звіт буде збережено в `backend/coverage/lcov-report/index.html`.

Окремо модульні або інтеграційні тести:

```
npx jest src/tests/unit
npx jest src/tests/integration
```

## 4. Запуск застосунку

Сервер:

```
cd backend
node server.js
```

API буде доступне за адресою `http://localhost:5000`, документація Swagger — `http://localhost:5000/api-docs`.

Клієнт:

```
cd frontend
npm run dev
```

Застосунок буде доступний за адресою `http://localhost:5173`.
